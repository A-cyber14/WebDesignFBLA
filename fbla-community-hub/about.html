About

Pinellas Connect is an FBLA Website Design project that demonstrates how residents could find community resources in Pinellas County.

About the Data

  • Every listing, event, phone number, and map pin is fictional. They show how the site works without sending anyone to a real service by mistake.
  • Phone numbers use the 555-0100 to 555-0199 range, which is reserved for fiction. Pins sit near each city's center, not at real addresses.
  • There are no fictional crisis lines. The Emergency page, header, and footer use only real, official numbers and links, with sources listed.
  • City names and categories are real, so the filters make sense for Pinellas County.

Design Decisions

  • Search first. A large search bar opens the home page, because many users go straight to search [1].
  • Filters above results. Category, city, and cost filters update results instantly, a common pattern for browsing large lists [2].
  • Simple layout. Each page has one main heading, white space between sections, and thin lines between items instead of boxes. Blue marks links and buttons; red is used only for 911.
  • Fewer cards. Resources and events are shown as lists, so people can scan names quickly. The home page has one photo, one map preview, and large emergency phone numbers.
  • Phone first. Most U.S. adults own a smartphone [3], so every page was laid out for phones first, then tablet and desktop.
  • The same parts on every page. One header, footer, list row, button, and pop-up design, so people learn the site once.
  • Inter typeface. Designed for reading on screens [4], with the device's own font as a backup.

Accessibility

  • Text meets WCAG 2.2 AA contrast of at least 4.5:1 [5].
  • Buttons and links are at least 24 by 24 pixels (WCAG 2.5.8), and most are 40–48 pixels [5][6].
  • Everything works with a keyboard, with a visible focus ring and a “Skip to main content” link.
  • Result counts and save confirmations are announced to screen readers (WCAG 4.1.3) [5].
  • The map has a list view with the same results, so nothing is shown only visually.
  • An accessibility button in the bottom-left corner of every page with larger text, high contrast, reading highlight, and reading spacing (WCAG 1.4.12). Settings are saved on this device.
  • Pages reflow at 320 pixels wide and at 200% text without sideways scrolling (WCAG 1.4.10, 1.4.4).
  • Animations turn off for people who prefer reduced motion [7].

How It Was Built

  • Plan: chose resident needs and categories, sketched phone-first wireframes, and mapped 8 pages.
  • Design: built one design system of colors, type sizes, spacing, and components.
  • Build: plain HTML, CSS, and JavaScript with all listings in one data file, so every page stays in sync.
  • Test: checked phone, tablet, and desktop layouts, keyboard use, contrast, and the map's offline fallback.
